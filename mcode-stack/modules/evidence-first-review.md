# 模块学习：evidence-first-review

> 仓库：https://github.com/MiniMax-AI/mcode-stack | 提交：88f84be | 分析日期：2026-11-10
> 源文件：stacks/ronny/skills/evidence-first-review/SKILL.md（73 行）

## 1 问题：这个模块解决什么问题

Agent 汇报「all tests pass, ready to merge」是**主张不是证据**。作者 agent 会在总结里说他想让你信的版本；如果先读总结再抽查证据，验证就被总结框定了。这个 skill 规定阅读顺序：**先读实际跑了什么（transcript/tool log），再读它怎么说**。

## 2 职责：它负责什么，不负责什么

- 负责：验收 agent 已完成的工作——证据核验、检查能力边界、挖出隐性决策、证伪尝试、最终裁决
- 不负责：diff 本身的干净上下文评审（显式交给 `independent-review`，L11-12 配对声明）

## 3 位置：整体架构中的角色

「Owning agent work」分组的核心（README 索引：when an agent reports done）。它处于**验收位**：subagent-split-check 管拆分、independent-review 管代码质量、本 skill 管"agent 说完成"那一刻的把关。

## 4 接口：对外公开的 API

- 触发场景（description）：MiniMax Code 会话 / 子代理 / 云端 agent 报告任务完成时，合并 PR 或采纳分析结论之前
- Output 契约：向他人汇报时**证据先行**（命令+结果），然后依次：查了什么、一件明确没查的、关键决策

## 5 数据：核心数据结构

核心"数据"是**检查能力对照表**（第 2 节）——每个绿勾必须填出「证明什么 / 不证明什么」两列：

| Check | Proves | Does not prove |
| --- | --- | --- |
| 新单测通过 | 该函数对该输入返回 X | 调用方是否传这个输入；测试可能与实现共享同一个错误假设 |
| pnpm typecheck | 类型对齐 | 运行时行为 |
| 带 mock 模型的 E2E | 循环接线正确 | 真实模型输出的任何行为 |

判定规则（L29）：右列填不出来 = 我们还不理解这个检查 = 不能当证据用。

## 6 执行：内部执行流程

六步走查：

1. **证据先于总结**（第 1 节）：打开 transcript 不打开最终消息；逐条核对支持"done"的命令——是否跑在最终代码上、exit 0、输出与总结所说一致。四个典型 gap：测试跑在最后一次编辑前 / `-t compaction` 类过滤器跳过了关键套件 / "fixed" 之前没有 reproduction / 构建通过靠跳步
2. **每个绿勾填两列表**（第 2 节）
3. **索要决策清单**（第 3 节）：选了哪些默认值、排除了什么范围、需求冲突时如何重新解释——"这些选择最终进入生产却没有经过任何人的决策"。逐条 accept/change/退回
4. **试着打破它**（第 4 节）：问"什么为真则此结论为错"，然后亲自验证那件事；对分析/文档类成果，打开两个引用来源、重算一个结论依赖的数字
5. **确认自己理解了**（第 5 节）：随机挑几行 diff 脱稿解释；大变更让 agent 出一份以三个问题结尾的报告，merge 前自己先答；争议裁决让 fresh subagent 辩反方；最后问一个干净上下文"What did I miss?"
6. **裁决三分支**（第 6 节）：Accept（证据匹配+决策已审+能说出缺口）/ Ask for more / Get a human review（高风险且说不出检查会漏什么）

## 8 设计：作者为什么这样设计

- **阅读顺序作为纪律**：证据/总结的先后顺序是本 skill 与普通 review 习惯的本质差异——先入为主的总结会框定验证
- **"说不清缺口就不能接受"**：接受标准的后半句（name the gap）比前半句更难也更关键，它把"检查过了"升级为"知道检查的边界"
- **隐性决策单独成节**：agent 的默认值选择是真实生产事故的高发区，却是人类验收最容易跳过的部分

## 9 替代方案：其他可能的设计与取舍

- **全自动验收**（跑测试脚本即可合并）：scale 最好但正是本 skill 反对的——测试可能根本没测到需求
- **强制双人评审**：成本高；本设计用"fresh context 问 What did I miss"替代了低成本版本的人类第二意见
- 代价：每单验收成本显著高于直接信总结；作者用"这是 owning 的成本"立场化了这个取舍

## 10 练习：建议你实现什么

最小实现：一个 TypeScript `evidenceAudit(commands: CommandLog[]): AuditResult`——输入命令执行日志（命令、时间戳、exit code、输出摘要、代码最后修改时间），输出每个"done 声明"的证据判定（验证四类 gap：顺序倒置、过滤逃逸、无复现修复、跳步）。vitest 用构造日志固化四类 gap 的检出规则。
